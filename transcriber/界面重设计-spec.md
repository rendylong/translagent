# 会议转录工作台 · 界面重设计 Spec

版本 v1.0(2026-10-23)· 状态:待评审
配套线框:会话内交互原型(5 个场景屏,编号与本文 S1–S9 对应)。

## 0. 背景与目标

用户三点诉求:

1. 上传文件与现场录制拆为**独立入口**;
2. 重构**整体信息架构**;
3. 说话人**声纹支持跨会议**(本 spec 覆盖其 UI 层;后端数据模型与管线方案见声纹评审报告,不在此重复)。

硬约束:纯原生 HTML/CSS/JS(无框架、无构建、无新依赖);仅本机运行;后端 Python 3.9;维持现有浅色视觉语言与单文件结构(`static/index.html` 内联样式 + 视图切换)。

## 1. 核心设计决策

### D1 双入口:平级 Tab
侧栏「新任务」区改为两个平级 Tab——**上传文件 / 现场录制**,各带独立内容面板。"素材从哪来"(入口)与"怎么处理"(设置)分为两层,现状的问题根源正是两层被压在同一个表单里。

### D2 转录设置二级化
事实:说话人数与语言不只影响上传——录音开始时同样快照消费(`index.html:378-384`)。因此设置在数据上是全局的,但在交互上收纳为二级:

- 转录设置 = **全局持久设置**,存 `localStorage`(键 `transcribe-settings`),默认:语言=中文,说话人=自动。
- **唯一编辑入口**:上传 Tab 底部的设置摘要行("中文 · 说话人 自动 · 修改"),点击展开侧栏内浮层(二级面板)。
- 录制 Tab **不放设置**:静默态一行小字"按当前转录设置处理:中文 · 说话人 自动";录制开始后快照**只读回显**在录制面板,共用设置不可改。
- 依据:录制是即时动作、配置是低频动作;全局化避免两个入口参数不一致。

### D3 信息架构分层
侧栏 = 发起与管理(新任务 Tab + 历史列表);主区 = 内容(空态/进行中/失败/文稿);二级层 = 转录设置、说话人库。桌面端与网页端共用同一份代码,差异仅默认 Tab 与录音源选项。

### D4 反馈规范
右上角 toast(4 秒自动消失,`aria-live=polite`)替换全部 5 处 `alert/confirm`;危险操作(删除/丢弃/放弃)用**行内二次确认**(按钮变"再点一次确认",3 秒窗口)。

### D5 hash 路由
`location.hash = '#<job_id>'`,启动时恢复,刷新不丢当前任务。

### D6 声纹 UI 集成(依赖后端声纹阶段 1/2)
说话人 chips 显示全局名 + 置信徽标(自动匹配 ✓ / 已确认 ✓ / 疑似 ?);疑似态给"确认 / 另存为新说话人"两个动作;改名即改全局库并跨任务重生成文稿;新增二级"说话人库"页。

## 2. 信息架构

```
会议转录工作台
├─ 侧栏
│  ├─ 新任务(Tab:上传文件 | 现场录制)
│  │  ├─ 上传面板:拖放/选择 → 已选文件 → 标题(可选)→ [开始转录] → 设置摘要行
│  │  │   └─ 二级:转录设置浮层(语言/说话人数/声纹开关)
│  │  └─ 录制面板:录音源 → [开始录制] → 录制态(REC·电平·快照回显·停止/丢弃)
│  ├─ 历史记录
│  │  ├─ 处理中(置顶;进度 + 排队位次)
│  │  └─ 今天 / 更早(终态;hover 删除;失败带错误摘要)
│  └─ 底部:说话人库入口(二级,阶段 3)
└─ 主区(视图)
   ├─ 空态:双入口引导
   ├─ 进行中:阶段条 + 进度 + 放弃
   ├─ 失败:结论化摘要 + 折叠详情 + 重跑/删除
   └─ 完成/文稿:标题编辑 · 元信息 · 播放器 · 说话人行 · 工具行 · 文稿
```

## 3. 屏幕规格

### S1 侧栏 · 上传 Tab(默认,web 端)

| 元素 | 规格 |
| --- | --- |
| Tab 条 | 两个等宽按钮,选中态黑底白字;`role=tablist/tab/tabpanel` |
| 拖放区 | 虚线框,文案"拖拽音频到此处,或点击选择";支持 m4a/wav/mp3/aac/flac/aiff(文案与 accept 对齐) |
| 已选文件 | 文件名 + 大小 + [更换];多文件时 toast"已选取第一个文件 N 个中的 1 个" |
| 标题 | 输入框,placeholder"标题(可选,默认用文件名)" |
| 提交 | 主按钮 [开始转录];提交中变"提交中…"并 disabled |
| 设置摘要行 | "将按:中文 · 说话人 自动 — [修改]" → 展开 S2 浮层 |
| 隐私 | 一行小字:"全部在本机处理,不上传任何外部服务" |

### S2 二级 · 转录设置浮层

- 形态:侧栏内绝对定位浮层卡(宽随侧栏),点外部/关闭钮收起;**即时生效**,无确定/取消。
- 字段:
  - 语言:自动 / 中文 / 英文(与现 `#lang` 口径一致);
  - 说话人:自动 / 1 / 2 / 3 / 4(后端允许 1–10,UI 先 4,口径在 spec 注明);
  - 自动匹配已知说话人(声纹开关,默认开;后端阶段 3 前隐藏)。
- 写 `localStorage`,摘要行即时刷新;录制 Tab 的回显文案同源。

### S3 侧栏 · 录制 Tab(桌面端默认)

状态机:静默 → 录制中 → 提交中 →(成功跳任务详情 | 错误)。

| 状态 | 规格 |
| --- | --- |
| 静默 | 录音源下拉(桌面:麦克风 / 系统声音 / 系统+麦克风;web 隐藏下拉,一行"将使用麦克风录音");默认标题"现场录音 M月d日 HH:MM";[● 开始录制] 主按钮;小字"按当前转录设置处理:中文 · 说话人 自动" |
| 录制中 | 红点 REC + `00:12:34`(tabular-nums)+ 电平条;快照回显"本次:系统+麦克风 · 中文 · 说话人 自动"(只读);主按钮 [■ 停止并转录],旁挂文字钮 [丢弃](行内二次确认);`body.recording` 挂载,上传 Tab 置灰禁用;Dock 角标 ● (桌面) |
| 提交中 | 按钮组 disabled,计时器定格,"提交中…" |
| 错误 | 面板内联错误条 + [重试];权限失败仍走现有引导窗 |

桌面专项:`win.on('close')` 读 `body.recording`,录制中先确认"关闭窗口将丢弃整场录音";`<1s` 误触丢弃改 toast 并说明阈值。

### S4 历史列表

- 分组:**处理中**组置顶(名称 · 阶段 · N% · 3px 进度条;排队任务显示"排队中 · 第 2 位",位次 = running 数 + 前面 queued 数,前端推导);其余按 `created_at` 分**今天 / 更早**。
- 每项:完成 = `创建时间 · 时长`;失败 = 时间 + 红"失败" pill + 60 字错误摘要副行。
- hover 右侧删除 icon(仅终态;进行中 disabled + title"任务处理中,暂不能删除");点击进详情;`role=button` + `tabindex=0` + Enter 键可达。
- 顶部当前选中项高亮;再次点击已选中项 = 无操作(维持现状)。

### S5 主区 · 空态

- 主文案:"上传一场会议录音,或直接开始录制";
- 两个入口按钮:[选择文件…](激活上传 Tab 并打开文件选择)、[● 开始录制](激活录制 Tab);
- 两套旧空态文案(253-266 / 623-624)合并为本渲染函数。

### S6 主区 · 进行中

- 六阶段圆点条 + 大号百分比 + 阶段文案 + 进度条(沿用现状视觉);
- 排队态显示位次;
- 新增 [放弃任务](行内二次确认;依赖后端 `POST /api/jobs/<id>/cancel`;上线前 disabled + 说明"任务处理中,暂不能删除");
- 耗时说明按时长估算替换固定文案(whisper 5 分 + diarization 约 0.13 倍速)。

### S7 主区 · 失败

- 首行结论化错误(前端关键词映射:"音频转码失败" / "未能从音频中识别出语音" / "转录服务内部错误"),whisper 原文折叠在"技术详情"里;
- [用原音频重跑](依赖后端 `POST /api/jobs/<id>/retry`,录音任务尤其重要)+ [删除任务](行内二次确认,文案含"将同时删除原始录音,无法恢复")。

### S8 主区 · 完成/文稿

按行重组(修现状四类功能混排):

1. **标题行**:h1 点击变输入框,Enter/blur 提交 `PATCH {title}`(后端已支持 `app.py:365-366`,自动重生成 transcript.md);右侧 [删除]。
2. **元信息行**:时长 · 段数 · 创建时间。
3. **播放器行**:`<audio>`(不变)。
4. **说话人行**(独立成行,不再被挤压):"说话人:" + chips。chip = 全局名 + 徽标:`✓`(自动匹配,灰)/`✓`(已确认,黑)/`? 0.62`(疑似,黄,附 [确认] [另存为新人]);改名 = 改全局库,全部任务生效;后端阶段 3 前退化为现状 chips(本地名)。
5. **工具行**:左 = 搜索框 + "12/230 段" + ✓跟随播放;右 = 导出 ▾(`<details>` 纯 CSS:MD/TXT/SRT/JSON)+ 📁 在 Finder 中显示。
6. **文稿正文**:三栏网格(时间戳 | 说话人 | 正文)与时间戳跳播逻辑不变;搜索加 200ms debounce。

### S9 二级 · 说话人库(阶段 3/4)

- 入口:侧栏底部"说话人库"文字链 + 主区视图;
- 列表:名字(可编辑)· 参与会议数 · 锚点段数 · 最近会议 · [改名] [删除];
- 疑似建议区:"说话人 3 ≈ Rendy · 相似度 0.58 — [确认合并] [保留为新人]";
- 阶段 4 增:[合并两人](选 a、b)、任务内 [重新匹配](用已落盘 embeddings 秒级重跑);
- 页脚说明:"声纹仅保存在本机,不出现在任何导出文件中"。

## 4. 全局交互规范

- **toast**:右上角,4 秒,`aria-live=polite`,错误类可手动关闭;替换 `index.html:348/366/397/411/620` 全部 alert。
- **行内二次确认**:按钮文字变"再点一次确认删除",3 秒未点复原;删除类文案必含后果(原始音频一并删除)。
- **录音保护**:`body.recording` 期间:web 挂 `beforeunload`;桌面 `close` 拦截;上传 Tab 与共用设置禁用。
- **键盘**:历史项、Tab、chips 全键盘可达;保留现有 `:focus-visible` 风格。

## 5. 数据与后端配合点

| 项 | 前端 | 后端 |
| --- | --- | --- |
| 转录设置 | localStorage 读写、摘要/回显 | 无改动 |
| 互斥与快照 | 录制开始快照 + 锁定 UI | 无改动 |
| hash 路由 | `#<job_id>` | 无改动 |
| 放弃任务 | 确认 + 调用 | 新增 `POST /api/jobs/<id>/cancel`(kill worker,置 error) |
| 失败重跑 | 按钮 | 新增 `POST /api/jobs/<id>/retry`(用已有 audio16k.wav 重入队) |
| 排队位次 | 前端推导 | 无改动(可选:meta 给 queue_pos) |
| 全局说话人 | chips/库页/确认交互 | 声纹阶段 1/2 的 `GET/PATCH /api/speakers`、merge、speaker_map |

## 6. 阶段切分与验收

| 阶段 | 内容 | 验收要点 |
| --- | --- | --- |
| P1 纯前端 | 双 Tab、设置二级浮层、录制态快照/锁定、丢弃分离、toast、历史分组/删除/失败摘要、标题编辑、hash 路由、空态合并 | 全程无 alert/confirm;录制中设置锁定且回显;两条入口互不干扰;改标题后 transcript.md 重生成 |
| P2 后端小配合 | cancel / retry / 排队位次 | 进行中可放弃且 worker 终止;失败任务重跑不丢音频 |
| P3 声纹 UI(依赖后端阶段 1) | 全局名 chips + 徽标、疑似确认、说话人库最小页、设置内声纹开关 | 同人跨会议显示同一名字;确认疑似后历史任务文稿同步 |
| P4 声纹完善(依赖后端阶段 2) | 合并/拆分/重新匹配 | 误并可通过合并拆分回滚,不重跑管线 |

## 7. 非目标

不引入框架/构建;不做云同步与多人协作;不改转录与声纹引擎本身;不做暗色主题(维持现状浅色,留待后续);不改 jobs 目录数据形状(transcript.json 的 speaker 仍为簇号,身份映射在 meta 层)。

## 8. 补记(2026-10-25)

2026-10-24 工作台设计评审修复已落地(spec 见 `docs/2026-10-24-workbench-review-fixes-spec.md`),对本 spec 的三处修订:

- **实时字幕入口降为动作行**:实时字幕与「往本页投喂任务」的 Tab 契约不符(字幕不在本页发生)——已从第三 Tab 降为「新任务」卡下的常驻动作行 `#liveRow`,Tab 条回归上传/录制两类;动作行状态点(空闲灰/进行中红+呼吸)与两态文案(「实时字幕 · 开悬浮窗或新标签页」/「字幕进行中 · 已开 HH:MM」)由 `GET /api/live/state` 驱动:独立常驻慢定时器(页面可见时 12s 一拉)+ visibilitychange 可见即刷 + 任务轮询 tick 顺带刷,失败静默保持上次状态,与任务轮询(pollTimer)是两条独立轻路径;整行可点,web 端以命名 target `livePanel` 开 `/live?mode=panel`(重复点击聚焦同一标签)。
- **hash 路由升级**:D5 的「启动时恢复一次」扩为完整路由层——`#` / `#<job_id>` / `#speakers` 三态,hashchange/popstate 双入口,程序化导航一律 `location.hash` 赋值;桌面「打开文稿」深链、浏览器返回键、说话人库刷新不丢由此成立。
- **空态变体收敛**:空态只有 upload/record 两变体,不再有 live 变体。
